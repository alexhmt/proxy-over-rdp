# Настройка RdpProxy

Эта справка описывает параметры готового комплекта. Для первой установки
используйте [README](../README.md). Выполняйте команды из папки RdpProxy
в Windows PowerShell 5.1 под тем же пользователем и в той же desktop-сессии,
где работает соответствующий адаптер.

## Выберите направление и порт

| Параметр | Действие |
| --- | --- |
| `-Mode ServerProxy` | Значение по умолчанию: SOCKS5 на сервере, сеть клиента |
| `-Mode ClientProxy` | SOCKS5 на клиенте, сеть сервера |
| `-Port PORT` | Порт SOCKS5, по умолчанию 1080; диапазон 1–65535 |
| `-AuthFile PATH` | Отдельный JSON с именем и паролем |

`PORT` и `PATH` — выбранный номер порта и путь к существующему файлу.
`-Port` и `-AuthFile` принимаются только на стороне SOCKS5. На противоположной
стороне их указание вызывает ошибку. Слушатель привязан к `127.0.0.1`;
изменение адреса привязки не предусмотрено.

Для ServerProxy запустите на клиенте:

```powershell
.\Start-Client.ps1 -Mode ServerProxy
```

На сервере в RDP-сессии запустите:

```powershell
.\Start-Server.ps1 -Mode ServerProxy -Port 1080
```

Для ClientProxy запустите на клиенте до RDP-подключения:

```powershell
.\Start-Client.ps1 -Mode ClientProxy -Port 1080
```

На сервере в RDP-сессии запустите:

```powershell
.\Start-Server.ps1 -Mode ClientProxy
```

Для смены режима завершите оба адаптера через **Выход**, затем запустите
их с одинаковым `-Mode`. Автоматическая COM-активация клиента использует
ServerProxy; для ClientProxy требуется явный запуск клиента до подключения.
Один клиентский процесс не обслуживает оба режима одновременно.

Прямой запуск EXE принимает `--mode server-proxy|client-proxy`, `--port PORT`
и `--auth-file PATH` с теми же ограничениями. Запуск без аргументов использует
ServerProxy. Параметр `--help` показывает справку в окне.

## Используйте несколько RDP-серверов

В ServerProxy один клиентский адаптер обслуживает несколько серверов.
На каждом сервере запустите свой серверный адаптер в своей RDP-сессии.
У каждого канала отдельные TCP-потоки; отключение одного RDP-контрола
закрывает только принадлежащие ему каналы.

На разных компьютерах допустим один и тот же порт. Разные RDP-сессии одного
Windows-сервера разделяют loopback, поэтому для них нужны разные порты,
например 1080 и 1081. Допускается один серверный адаптер на desktop-сессию.
Auth-файл выбирается отдельно на каждой стороне со слушателем.

В ClientProxy новые запросы принимаются только при одном готовом канале.
Если их несколько, запрос отклоняется до отправки OPEN: сервер не выбирается
автоматически. Несколько TCP-потоков внутри одного канала допустимы.

## Используйте автоматически созданный пароль

Без `-AuthFile` слушатель создаёт имя `rdp` и случайный пароль при запуске.
Параметры сохраняются в профиле текущего пользователя:

| Режим | Экспорт параметров на стороне слушателя |
| --- | --- |
| ServerProxy | `%LOCALAPPDATA%\RdpProxy\session-SESSION_ID.json` |
| ClientProxy | `%LOCALAPPDATA%\RdpProxy\client-session-SESSION_ID.json` |

`SESSION_ID` — числовой идентификатор Windows-сессии. Точный путь доступен
в `CredentialFile` результата `Get-ProxyStatus.ps1`. JSON содержит `Host`,
`Port`, `Username`, `Password`, `Side`, `Mode`, `Authentication`, `SessionId`
и `ProcessId`.

Пароль сохраняется при переподключении RDP и меняется после перезапуска
процесса со слушателем. При штатном завершении экспорт удаляется; после
аварии он может остаться и заменяется при следующем запуске.
Правка экспорта не меняет пароль работающего процесса.

Пароль хранится в JSON открытым текстом. Каталог экспорта защищён ACL
текущего пользователя. Процессы этого пользователя и администратор ОС
остаются доверенными сторонами. Не публикуйте auth-файлы, экспорт сессии
или переменные с их содержимым.

## Задайте имя и пароль

На стороне SOCKS5 создайте отдельный auth-файл:

```powershell
.\New-ProxyAuth.ps1 -UserName rdp
```

Скрипт запросит пароль скрытым вводом и создаст
`%LOCALAPPDATA%\RdpProxy\auth.json` с ACL текущего пользователя. Существующий
файл не перезаписывается. Параметр `-Path` выбирает другой путь, а `-WhatIf`
показывает действие без запроса пароля и записи файла.

Для ServerProxy передайте файл серверу:

```powershell
.\Start-Server.ps1 -AuthFile "$env:LOCALAPPDATA\RdpProxy\auth.json"
```

Для ClientProxy передайте файл клиенту:

```powershell
.\Start-Client.ps1 -Mode ClientProxy `
    -AuthFile "$env:LOCALAPPDATA\RdpProxy\auth.json"
```

Противоположную сторону запустите с тем же режимом без `-AuthFile`.
Проверка пароля происходит локально до открытия TCP-потока через DVC;
пароль в канал RDP не передаётся.

Для ручного создания используйте [auth.example.json](../auth.example.json).
Замените оба заполнителя собственными значениями. Требования к файлу:

- UTF-8 с BOM или без него; размер от 1 до 16384 байт.
- `Username` и `Password` — строки длиной 1–255 байт в UTF-8 без управляющих
  символов, включая NUL и переводы строк.
- Имена полей нечувствительны к регистру; повтор одного из этих полей — ошибка.
- Файл должен отличаться от создаваемого экспорта сессии. Не используйте
  session-файл или ссылку на него как источник `-AuthFile`.

Неверный или недоступный файл приводит к ошибке запуска без перехода
на случайный пароль. После изменения auth-файла перезапустите слушатель.
Исходный auth-файл приложение только читает и при завершении не удаляет.

Для не-ASCII символов программа SOCKS5 должна передавать имя и пароль
в UTF-8. Для curl используйте имя без двоеточия: оно разделяет имя и пароль.

## Скачайте файл через прокси

`Download-ProxyFile.ps1` использует установленный `curl.exe` на стороне
слушателя. Это сетевой запрос: выберите ресурс, доступ к которому хотите
проверить. Пример с ограничением скорости и продолжением загрузки:

```powershell
.\Download-ProxyFile.ps1 -Url 'DOWNLOAD_URL' `
    -Output '.\downloads\file.zip' -CreateDirectories `
    -Resume -Retry 5 -LimitRate 2M
```

Замените `DOWNLOAD_URL` адресом нужного файла. Для запуска на клиенте
в ClientProxy добавьте `-Mode ClientProxy`.

| Параметр | Значение и действие |
| --- | --- |
| `-Url` | Обязательный адрес ресурса |
| `-Output`, `-OutFile` | По умолчанию `.\test__.zip`, относительно текущей папки PowerShell |
| `-Resume` | Продолжить тот же файл с текущего размера; по умолчанию выключено |
| `-Retry` | Число повторов после первой попытки: 3; 0 отключает повторы |
| `-RetryDelaySec` | Пауза 2 секунды; 0 использует возрастающую задержку curl |
| `-RetryAllErrors` | Повторять все ошибки; нужен curl 7.71+ и `-Retry` больше 0 |
| `-ConnectTimeoutSec` | 30 секунд на подключение; 0 использует значение curl |
| `-MaxTimeSec`, `-TimeoutSec` | Лимит каждой попытки; 0 — без лимита |
| `-RetryMaxTimeSec` | Бюджет для начала повторов с учётом пауз; 0 — без лимита |
| `-LimitRate` | Байт/с; суффиксы `K`, `M`, `G` кратны 1024 |
| `-Quiet` | Скрыть прогресс, сохранив сообщения об ошибках |
| `-CreateDirectories` | Создать каталоги выходного файла |
| `-Mode` | ServerProxy по умолчанию; выбирает экспорт текущей сессии |
| `-ProxyConfigFile` | Явный экспорт с `Host`, `Port`, `Username`, `Password`; приоритетнее `-Mode` |

`-ProxyConfigFile` принимает экспорт слушателя, а не auth-файл, где нет
адреса и порта. Скрипт передаёт пароль curl через UTF-8 stdin, а не аргументы
процесса; настройки curlrc и NO_PROXY не подменяют выбранный прокси.

Без `-Resume` существующий файл заменяется. Продолжение требует того же
ресурса и поддержки докачки сервером. Повтор curl может начать неудачную
попытку заново; это не гарантия продолжения с последнего полученного байта.
`-RetryMaxTimeSec` не прерывает уже начатую попытку. `Retry-After` сервера
может увеличить паузу. `-RetryAllErrors` повторяет и постоянные HTTP-ошибки,
например 404.

Ненулевой код curl вызывает ошибку скрипта. Полная справка:

```powershell
Get-Help .\Download-ProxyFile.ps1 -Full
```

После запуска проверьте результат программы и данные в выходном файле.
Рост счётчиков RdpProxy сам по себе не подтверждает успешную загрузку.
Для поиска ошибок используйте [диагностику](DIAGNOSTICS.md).
