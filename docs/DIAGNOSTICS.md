# Диагностика RdpProxy

Используйте эту инструкцию, чтобы прочитать локальное состояние и найти
причину сбоя. Команды статуса и чтения журналов не отправляют сетевые
запросы. Проверку передачи выполняйте отдельно через нужную программу.

## Прочитайте состояние

Выполните команду в папке RdpProxy под тем же пользователем, в той же
desktop-сессии и с тем же уровнем прав, что и адаптер. На клиенте:

```powershell
$status = .\Get-ProxyStatus.ps1 -Side Client
$status | Select-Object Build, Mode, SessionId, ProcessId,
    ChannelCount, ReadyChannelCount, Host, Port, DiagnosticLog
$status.Channels | Format-Table OwnerId, ChannelId, Connected,
    Streams, SentBytes, ReceivedBytes
```

На сервере используйте `-Side Server`. Окно **Статус…** в меню трея
показывает основные поля без пароля.

| Поле | Значение |
| --- | --- |
| `Build` | Версия сборки из `AssemblyInformationalVersion`, например `0.1.0+COMMIT_SHA` |
| `Mode` | Выбранное направление прокси |
| `ChannelCount` | Число локальных объектов DVC, включая ещё не готовые |
| `ReadyChannelCount` | Число каналов, завершивших HELLO |
| `Host`, `Port`, `CredentialFile` | Параметры локального SOCKS5; `null` на стороне исходящих подключений |
| `OwnerId` | Локальный идентификатор владельца RDP-контрола |
| `ChannelId` | Локальный идентификатор DVC; меняется при переподключении |
| `Connected` | HELLO завершён, канал не остановлен |
| `Streams` | Число потоков в канале |
| `SentBytes` | TCP-данные, поставленные в исходящую очередь DVC |
| `ReceivedBytes` | TCP-данные, принятые из прикладных DATA-кадров |
| `ReceivedFrames` | Число полученных прикладных кадров, включая управляющие |
| `ReceiveIdleMs` | Время без входящих прикладных кадров |
| `NativeWritePendingMs` | Длительность текущей native-записи; 0, если записи нет |

OwnerId и ChannelId не являются именами серверов или средствами
аутентификации. Их значения локальны и не обязаны совпадать на двух концах.
`Connected=True` подтверждает готовность канала, но не доступность
конкретного ресурса. `SentBytes` не является подтверждением доставки,
а `ReceivedBytes` — подтверждением обработки данных конечной программой.

## Откройте журналы

Меню **Открыть журнал** открывает текущий файл. Его путь также доступен
в `DiagnosticLog`. Журналы находятся в `%LOCALAPPDATA%\RdpProxy\logs`;
имя включает сторону, Windows SessionId, PID и время запуска.

Для чтения последних записей в том же PowerShell-окне выполните:

```powershell
Get-Content -LiteralPath $status.DiagnosticLog -Tail 80
```

Журнал содержит время UTC, монотонный счётчик времени, события каналов
и потоков, типы исключений и коды ошибок. Адреса целевых ресурсов,
credentials и содержимое TCP-передач не записываются. При переполнении
очереди диагностики отдельные записи могут быть пропущены.

При размере больше приблизительно 2 МиБ файл переносится в соседний `.1`.
Ошибка записи журнала не останавливает транспорт. Старые журналы разных
запусков автоматически не удаляются.

## Найдите причину по симптому

| Симптом | Что проверить |
| --- | --- |
| Start-скрипт завершился, значка нет | Совпадение комплекта, наличие Desktop Runtime для small, интерактивный сеанс, окно ошибки запуска |
| Ошибка чтения статуса | Работает ли адаптер нужной стороны; совпадают ли пользователь, сессия и уровень прав |
| `Cannot open DVC`, Win32=31 | Клиентский журнал, наличие `plugin-initialize`, COM-регистрацию и разрешение DVC политиками; код 31 сам по себе не устанавливает причину |
| Нет `plugin-initialize` | Регистрацию под пользователем RDP-клиента; для x86 mRemoteNG также Registry32; полный перезапуск RDP-клиента после регистрации |
| Канал есть, но `Connected=False` | Совпадение Mode и версии двух сторон, ошибки HELLO в обоих журналах |
| Ошибка занятого порта | Другой процесс или RDP-сессию на том же компьютере; выберите свободный `-Port` на стороне SOCKS5 |
| `client-proxy-ambiguous` | Несколько готовых каналов ClientProxy; оставьте один серверный адаптер |
| SOCKS-аутентификация отклонена | Актуальный экспорт сессии, выбранный порт, имя и пароль; после перезапуска случайный пароль меняется |
| `connect-failed` | Доступность DNS и TCP-ресурса со стороны исходящих подключений выбранного режима |
| `heartbeat-expired` или рост `ReceiveIdleMs` | Состояние RDP/VPN и события обоих концов; отсутствие входящих кадров не доказывает сбой конкретного TCP-ресурса |
| Большой `NativeWritePendingMs` | Состояние RDP и native-записи; сопоставьте временные метки двух журналов |
| `Invalid frame length` или ошибка native DVC | Целостность комплекта и совместимость двух сторон; сохраните журналы до перезапуска |

Регистрация находится в двух представлениях HKCU по путям:

- `Software\Microsoft\Terminal Server Client\Default\AddIns\RdpProxy`;
- `Software\Classes\CLSID\{6F75C6EF-33F1-4F21-AE88-9EB09F65B8F1}\LocalServer32`.

Путь `LocalServer32` должен указывать на существующий клиентский EXE
выбранного комплекта. Для повторной регистрации используйте
`Register-Client.ps1`, затем пересоздайте RDP-подключение. Для mRemoteNG
требуется полный перезапуск приложения.

## Включите замеры времени

Замеры выключены по умолчанию. Перед запуском соответствующего адаптера
задайте в его PowerShell-окне:

```powershell
$env:RDPPROXY_TIMING = '1'
```

Запустите адаптер через `Start-Client.ps1` или `Start-Server.ps1` с нужными
параметрами. Работающий процесс не увидит изменение переменной; для него
нужен перезапуск. Явный запуск обеспечивает наследование переменной;
не полагайтесь на её передачу при автоматической COM-активации.

Во время передачи прочитайте агрегаты, например на клиенте:

```powershell
$status = .\Get-ProxyStatus.ps1 -Side Client
$status.Channels | Select-Object ChannelId, Streams, Timings |
    ConvertTo-Json -Depth 6
```

На сервере используйте `-Side Server`.

| Метрика | Измеряемый интервал |
| --- | --- |
| `QueueToWrite` | От постановки кадра в очередь до первой native-записи; для объединённого кредита — от первого накопленного кредита |
| `NativeWrite` | На клиенте — вызов COM Write; на сервере — от начала записи до наблюдения её завершения |
| `CreditWait` | Непрерывное ожидание доступного кредита, включая повторные пробуждения |

Каждая метрика содержит `Count`, `MeanMs`, `MaxMs`, `P50UpperMs`,
`P95UpperMs` и `P99UpperMs`. Перцентили — верхние границы двоичных
интервалов гистограммы, а не точные значения. Снимок при работающих
потоках приблизительный. Агрегаты накапливаются за жизнь DVC и сбрасываются
при создании нового канала; без переменной поле `Timings` равно `null`.

`NativeWrite` не измеряет доставку получателю. Серверное значение включает
задержку обработки завершения в цикле ввода-вывода. В `CreditWait` входят
отменённые ожидания. Сравнивайте одинаковые режимы, направление передачи,
ресурс и условия RDP; одной метрики недостаточно для вывода о скорости.

Для следующего запуска без замеров удалите переменную:

```powershell
Remove-Item Env:\RDPPROXY_TIMING -ErrorAction SilentlyContinue
```

## Опишите воспроизводимый сбой

Укажите версию `Build` обеих сторон, Windows, используемый RDP-клиент,
Mode, число готовых каналов, последовательность действий и время сбоя.
Приложите соответствующие фрагменты журналов и результат конечной
программы. Удалите сведения, которые не хотите публиковать; не прикладывайте
auth-файл, экспорт сессии или вывод переменных с паролем.

CI проверяет сборку и упаковку. Он не запускает GUI, COM-плагин в RDP-клиенте
или передачу по реальной RDP-сессии. Для версии 0.1.0 интерактивная работа
после изменений трея остаётся непроверенной; не трактуйте зелёный workflow
как подтверждение этого сценария.
