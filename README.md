# RdpProxy — SOCKS5 через RDP

RdpProxy передаёт TCP-соединения SOCKS5 через динамический виртуальный канал
RDP (DVC). Программы используют локальный прокси, а DNS-запросы и подключения
к ресурсам выполняет противоположная сторона RDP.

| Режим | Где работает SOCKS5 | Где выполняются DNS и исходящие TCP |
| --- | --- | --- |
| `ServerProxy` — по умолчанию | RDP-сервер | Клиентский компьютер |
| `ClientProxy` | Клиентский компьютер | RDP-сервер |

```text
ServerProxy: программа на сервере → SOCKS5 → RDP → клиент → ресурс
ClientProxy: программа на клиенте → SOCKS5 → RDP → сервер → ресурс
```

Версия **0.1.0** предназначена для предварительного знакомства и проверки.
Клиент и сервер работают как приложения Windows с меню в трее. Работа
интерфейса в реальной пользовательской RDP-сессии после изменений трея ещё
не подтверждена. Успешная CI-сборка подтверждает сборку и упаковку, но
не работу GUI, COM-плагина или передачи данных через RDP.

## Требования

- Целевая конфигурация: Windows x64, классический `mstsc.exe` на клиенте
  и собственная интерактивная RDP-сессия на сервере. Ориентиры совместимости —
  Windows 10 и Windows Server 2016.
- На обеих сторонах нужен рабочий стол Windows с областью уведомлений.
  Сервер нельзя запускать через службу, WinRM или Session 0.
- Для скриптов нужен Windows PowerShell 5.1 Desktop. PowerShell 7 и .NET SDK
  для запуска готового архива не требуются.
- Политики среды должны разрешать пользовательские DVC и запуск компонентов
  без цифровой подписи. Подписание исполняемых файлов в проекте не настроено.

Приложения используют `net8.0-windows` и Windows Forms. Поддержка .NET 8
завершилась **10 ноября 2026 года** по
[политике Microsoft](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).
Версия 0.1.0 сохраняет эту целевую платформу; переход на .NET 10 LTS выделен
в отдельную работу до стабильного выпуска.

## Выберите архив

Опубликованные сборки ищите в разделе
[Releases](https://github.com/alexhmt/proxy-over-rdp/releases).
Для одной версии используются два варианта:

| Архив | Что требуется на компьютере |
| --- | --- |
| `RdpProxy-0.1.0-win-x64-full.zip` | Runtime включён в архив |
| `RdpProxy-0.1.0-win-x64-small.zip` | Установленный .NET 8 Desktop Runtime x64 |

.NET Framework 4.x и обычный .NET Runtime без Windows Desktop не заменяют
Desktop Runtime. Все файлы выбранного комплекта `bin\win-x64` должны
находиться вместе. На обеих сторонах используйте одну версию RdpProxy.

Архив содержит приложения, семь пользовательских PowerShell-скриптов,
этот README, инструкции по настройке и диагностике, пример auth-файла
и лицензии. Исходники, инструменты сборки и разработки в него не входят.

## Запустите ServerProxy

1. Распакуйте архив на клиентском компьютере, например в `C:\Tools\RdpProxy`.
   Откройте обычный Windows PowerShell под пользователем, который запускает
   RDP-клиент, и зарегистрируйте плагин:

   ```powershell
   Set-Location C:\Tools\RdpProxy
   .\Register-Client.ps1
   .\Start-Client.ps1
   ```

2. Найдите значок **C** в трее. Закройте прежнее RDP-окно без выхода из
   пользовательского сеанса, затем запустите новый процесс `mstsc.exe`
   и подключитесь к серверу.
3. Распакуйте весь комплект на сервере. Внутри своей RDP-сессии выполните:

   ```powershell
   Set-Location C:\Tools\RdpProxy
   .\Start-Server.ps1
   ```

4. Откройте **Статус…** через значок **S** на сервере и дождитесь готового
   канала. На сервере прочитайте состояние и путь к параметрам SOCKS5:

   ```powershell
   .\Get-ProxyStatus.ps1 -Side Server
   ```

По умолчанию слушатель использует `127.0.0.1:1080`. Поле `CredentialFile`
указывает локальный JSON-файл с адресом, портом, именем и паролем.
Перенесите эти значения в настройки нужной программы и включите разрешение
имён через SOCKS5. Не публикуйте содержимое файла.

Start-скрипты возвращают управление сразу: PowerShell можно закрыть.
Сам возврат из скрипта не означает готовность канала. Проверка статуса
читает локальный named pipe и не отправляет сетевой запрос.

Клиент может запускаться автоматически через COM. Такой запуск использует
`ServerProxy`. Для запуска с параметрами используйте `Start-Client.ps1`.
После регистрации не перемещайте папку: COM хранит абсолютный путь к EXE.

## Подключитесь через mRemoteNG

Для 32-разрядного mRemoteNG на Windows x64 нужна регистрация в обеих
ветках COM: Registry32 и Registry64. `Register-Client.ps1` создаёт обе
регистрации в HKCU. Сам RdpProxy остаётся отдельным 64-разрядным процессом
COM LocalServer; приложение x86 собирать не нужно.

1. Запустите `Register-Client.ps1` под пользователем mRemoteNG.
2. Полностью закройте и заново откройте mRemoteNG, сохранив удалённый сеанс
   без Logoff.
3. Подключитесь к серверу и запустите `Start-Server.ps1` в RDP-сессии.
4. Проверьте готовность канала в статусе и события `plugin-initialize`,
   `plugin-connected`, `hello-complete` в журнале клиента.

Регистрация поддерживает такой способ загрузки, но работа комплекта 0.1.0
через mRemoteNG требует отдельной проверки в целевой среде.

## Используйте сеть сервера на клиенте

Остановите оба адаптера через **Выход**. На клиенте перед новым RDP-подключением
запустите:

```powershell
.\Start-Client.ps1 -Mode ClientProxy -Port 1080
```

Внутри RDP-сессии запустите:

```powershell
.\Start-Server.ps1 -Mode ClientProxy
```

В этом режиме программы клиентского компьютера используют
`127.0.0.1:1080`, а ресурсы и DNS доступны со стороны сервера. Оставьте
подключённым один серверный адаптер: при нескольких готовых каналах
ClientProxy отклоняет новые SOCKS-запросы.

`-Mode` должен совпадать на обеих сторонах. `-Port` и `-AuthFile` допустимы
только на стороне SOCKS-слушателя. Подробности о паролях, нескольких серверах
и параметрах запуска — в [настройке](docs/CONFIGURATION.md).

## Управляйте приложением

В трее клиента отображается **C**, сервера — **S**. Жёлтый цвет означает
запуск или ожидание канала, зелёный — наличие готового канала, серый —
завершение. Меню **Статус…** и двойной щелчок открывают состояние адаптера.
**Открыть журнал** открывает текущий диагностический файл.

Закрытие окна статуса оставляет приложение в трее. **Выход** закрывает SOCKS
и DVC, прерывая активные передачи, но не выполняет Logoff RDP-сессии.
Перед заменой файлов остановите свои адаптеры и сохраните прежний комплект
для отката. Заменяйте комплект целиком. При смене пути повторите регистрацию.

Для удаления сначала завершите адаптеры, затем на клиенте выполните:

```powershell
.\Unregister-Client.ps1
```

После этого папку приложения можно удалить. Скрипт удаляет только
регистрацию RdpProxy текущего пользователя; личный auth-файл и журналы
не удаляются.

## Возможности и ограничения

- SOCKS5 CONNECT с обязательными именем и паролем; TCP, IPv4, IPv6 и доменные
  имена. UDP ASSOCIATE, BIND, ICMP и HTTP CONNECT не реализованы.
- До 64 TCP-потоков на DVC; блок данных до 16 КиБ, окно до 256 КиБ на
  направление каждого потока.
- ServerProxy обслуживает несколько RDP-серверов одним клиентским процессом.
  На одном Windows-сервере разные RDP-сессии должны использовать разные порты.
- Обрыв RDP закрывает активные TCP-соединения. Повторное открытие DVC
  не восстанавливает передачи; повтор запроса выполняет программа.
- Доступны все назначения, разрешённые сетью противоположной стороны.
  RdpProxy не меняет системные маршруты, DNS, firewall или политики запуска.
- RD Gateway, каскадный RDP, Windows App, другие RDP-клиенты и несколько
  desktop-сессий одного SID на клиенте не входят в подтверждённую конфигурацию.

## Сборка и CI

Исходники и инструменты сборки находятся в
[репозитории](https://github.com/alexhmt/proxy-over-rdp).
Для сборки используется Windows и SDK, закреплённый в `global.json`:
**10.0.404**. Версия SDK не меняет целевую платформу и требуемый runtime:
приложения по-прежнему используют .NET 8 Desktop.

`Build.ps1` принимает `-WorkRoot`, `-OutputDirectory`, `-FrameworkDependent`,
`-Version` и `-SourceRevision`. Полный вариант включает runtime; ключ
`-FrameworkDependent` создаёт вариант для установленного runtime.
`Package.ps1` принимает `-PublishDirectory`, `-OutputDirectory`, `-Version`,
`-Variant full|small`, `-SourceRevision`, `-Repository`, `-RunUrl`
и `-SdkVersion` и упаковывает готовую публикацию.

В клоне репозитория соберите и упакуйте полный вариант:

```powershell
$revision = (git rev-parse HEAD).Trim()
.\Build.ps1 -Version 0.1.0 -SourceRevision $revision
.\Package.ps1 -PublishDirectory '.\artifacts\publish\full' `
    -OutputDirectory '.\artifacts\packages' -Version 0.1.0 `
    -Variant full -SourceRevision $revision -SdkVersion 10.0.404
```

Результат — `RdpProxy-0.1.0-win-x64-full.zip` и файл `.zip.sha256`.
Для компактного варианта добавьте `-FrameworkDependent` к Build,
передайте Package каталог `artifacts\publish\small` и `-Variant small`.
Каталог публикации должен быть новым или пустым; готовые архивы
не перезаписываются. `-WorkRoot` позволяет вынести временную сборку
на локальный диск.

GitHub Actions запускается для push в `main`, pull request, вручную и по
тегам `v*`. Он выполняет четыре публикации: клиент и сервер для полного
и компактного вариантов. Выпуск по тегу `v0.1.0` создаётся как
**draft prerelease** с архивами и контрольными суммами. Метка `Build` берётся из
`AssemblyInformationalVersion`, например `0.1.0+COMMIT_SHA`.

Workflow не запускает GUI или реальный RDP-сеанс. Перед стабильным выпуском
нужны отдельная проверка целевой среды и переход на поддерживаемую платформу.
